# AI-Buddy: SDD и карта проверок MVP

Состояние: 16.11.2026. Источник требований хакатона — официальный кейс Авито, локальная копия которого не входит в репозиторий. Эта страница описывает **реализованный** прототип и проверяемые критерии; детали контрактов находятся в [PR/CI](ci.md), [LLM](llm.md), [skills](skills.md) и [team-help](team-help.md). Корпоративные данные, Git, CI и адресаты здесь синтетические.

## Цель и границы

Стажёр получает первую линию помощи по материалам команды. AI-Buddy ищет подтверждённые инструкции, выбирает разрешённый skill/инструмент и, когда ответа нет, готовит содержательный черновик наставнику. Главный проверяемый сценарий — самопроверка PR №17. Целевая метрика — уменьшение доли рутинных обращений к наставнику; **измеренного улучшения пока нет**. Реальные API Авито, сообщения реальным ботам, исполнение кода PR и автоматическое одобрение PR не входят в MVP.

## Архитектура и границы доверия

`React → Go HTTP API/очередь → team config + skills → MCP knowledge/Git/skills mocks → JSON-хранилище`. В Live к разрешённым сценариям подключается OpenAI-совместимая модель. Backend проверяет права, источники, SHA, формат результата и подтверждение записи. Модель не получает инструмент отправки ревью. Frontend отображает результат и ссылки; cookie привязывает историю к владельцу. Изменения diff и документы не являются инструкциями с правом менять полномочия. Подробные поля, ошибки и ограничения описаны в документах выше.

## Приёмочные сценарии

| Требование | Ожидаемый результат | Реализация | Проверка |
|---|---|---|---|
| Командный ответ | «Как оформить пулреквест?» открывает существующую PR-инструкцию со ссылкой; неизвестный GitLab не получает инструкцию другого продукта | `teams/demo-backend/`, `internal/integration/mcpknowledge`, `internal/teamhelp` | `TestPullRequestSynonymsFindExistingInstructions`, `TestGenericCISectionsDoNotAnswerUnknownProductAccess`, E2E первой линии |
| Профильный помощник | HR/отпуск/БД → профиль из каталога, без утверждения об отправке сообщения | `context.json`, `teamhelp.Handoff` | `TestTeamAnswersHaveSpecificSourcesAndTargets`, E2E первой линии |
| Неизвестный вопрос | Поиск пуст → предложение наставника; после согласия черновик содержит исходный вопрос и результат поиска | `service`, `teamhelp.Escalate` | `help_test.go`, HTTP/E2E первой линии |
| PR Self-Review | Skill получает PR, diff, правила и CI того же SHA; возвращается отчёт с доказательствами и границами анализа | `skills/pr-self-review/SKILL.md`, `service/review.go`, MCP Git | Go `review`/`live` tests, E2E PR и CI |
| Новый mock CI | Новый run ID для актуального SHA; код PR не выполняется | MCP Git fixtures, `ReviewPanel` | E2E PR и mock CI |
| Повтор AI-анализа | Последний результат CI используется без создания нового запуска | `useBuddy.recheck(false)` | E2E PR и mock CI |
| Запрос наставнику | Отдельное подтверждение, квитанция сохраняется и отображается; новый SHA требует нового запроса, повтор прежнего SHA идемпотентен | `service/review.go`, MCP Git, `repository` | E2E новая версия PR, Go HTTP/Git tests |
| Ошибки и восстановление | Некорректный ответ модели не сохраняется, временную ошибку можно повторить, история живёт после перезапуска | `llm`, очередь, JSON-хранилище | `client_test.go`, `recovery_test.go`, E2E временный сбой |
| Права и данные | Чужой PR/операция недоступны; демо-данные синтетические; ключ только на backend | HTTP session, MCP auth, `.env.example` | Go HTTP/MCP tests, проверка конфигурации |

Статусы — не обещание качества реальной модели. Контракт Live проверяется тестовым API. Вопрос о доступе к Grafana через `openrouter/free` прошёл с проверенными ссылками; после увеличения лимитов прямой и чатовый Live PR Self-Review прошли с одним замечанием и правильным SHA. Повторный smoke проверил документ, Grafana, неизвестный GitLab, PR, подтверждённую mock-квитанцию и восстановление после перезапуска. Перед записью повторите короткий контрольный прогон.

## Воспроизведение и доказательства

Из корня: `make up`, открыть `http://127.0.0.1:5173/`, спросить о PR, проверить исходный FAILED CI, имитировать новый CI, выполнить `make demo-fixed`, обновить AI-анализ, подтвердить запрос и проверить квитанцию с новым SHA. `make reset` удаляет историю Compose, поэтому применять только к демонстрационному экземпляру. Команды тестов и отчёта покрытия **строк** находятся в [README](../README.md#тесты-и-покрытие). Отчёт об актуальном покрытии следует создавать после финального прогона; проценты прежнего аудита не переносятся автоматически на новые изменения.

Для продуктовой гипотезы проведите одинаковые типовые задачи с Buddy и без него: доля решённых без наставника, минуты наставника на случай, число ложных эскалаций и экспертная оценка правильности. До пилота результат формулируется как потенциальное снижение рутины.
