# Пошаговая подготовка сдачи

Порядок: автоматические проверки и отчёты → контрольный Live-прогон → запись видео → PDF и ссылки в комплекте сдачи. Команды ниже выполняются в PowerShell из корня репозитория. Уже заполненный `.env` сохраняйте: копировать поверх него `.env.example` не нужно.

## 1. Проверить код и собрать отчёты

Нужны Git, Go 1.26.2, Node.js 22.12+ и установленный Microsoft Edge. При первом запуске потребуется интернет для npm и закреплённого инструмента преобразования покрытия.

```powershell
Set-Location 'C:\Users\Amir\Documents\ChatGPT\Хакатоны\ai-buddy'
git pull --ff-only
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\prepare-submission.ps1
```

Скрипт проверяет Go-тесты, vet/build, frontend-сборку, unit/E2E и решение учебного задания. Он измеряет **строки** всего приложения, включая пакеты без собственных тестов, и требует больше 80% отдельно для backend и frontend. Тесты используют Demo и тестовый API модели: платных Live-вызовов и изменения `.env` здесь нет. При ошибке или недостаточном покрытии готовый ZIP не создаётся.

В конце появится путь вида `artifacts/submission-20261116-120000-000.zip`. Откройте соответствующую папку:

- `README.md` — результат, SHA проверенного коммита и границы проверки.
- `summary.json` — числа покрытых/всех строк, проценты и статус рабочего дерева.
- `backend/coverage.html` — удобный просмотр Go-отчёта; `coverage.xml` и `coverage.out` — исходные данные.
- `frontend/coverage/index.html` — отчёт фронтенда; рядом `lcov.info` и `coverage-summary.json`.
- `frontend/playwright-report/index.html` — результат браузерного прогона.
- `backend/checks.log`, `frontend/checks.log`, `training/checks.log` — логи проверок.

**Отчёт нужен:** он прямо указан в §10 ТЗ главы команды: «Отчёт о покрытии прикладного кода более 80%, включая frontend и backend». Самих процентов в презентации недостаточно для воспроизведения проверки. Приложите ZIP или доступную ссылку на него. Презентация и видео в этот архив автоматически не добавляются.

`artifacts/` исключён из Git и Docker-контекста. Пакет состоит из отчётов; `.env`, ключи модели и история приложения туда не копируются. Упаковывать весь рабочий каталог проекта не требуется. После изменения кода пересоберите отчёт. Учебный `training/orders` — отдельное упражнение с намеренно ошибочной исходной версией; его эталон проверяется отдельно и не включается в метрику приложения AI-Buddy.

Для другого браузера: `-Browser chrome` либо `-Browser chromium`. Для Chromium предварительно выполните из `frontend` команду `npx playwright install chromium`. Для Microsoft Edge отдельная установка Playwright-браузера не требуется. Порты 4173 и 18080 должны быть свободны.

## 2. Поднять приложение и проверить Live

1. Запустите Docker Desktop и дождитесь готовности Engine.
2. В уже заполненном корневом `.env` проверьте **только у себя**, что выбран `BUDDY_MODE=live`, задан провайдер/модель/ключ и `LLM_TIMEOUT=45s`. Значения ключа не показывайте в записи. Автотесты из шага 1 не подтверждают доступность этого провайдера.
3. Выполните:

```powershell
make up
make ps
make demo-reset
```

Оба сервиса должны быть `healthy`. По умолчанию адрес — `http://127.0.0.1:5173/`; если в `.env` изменён `BUDDY_PORT`, используйте его. `make demo-reset` выбирает исходный PR, базовый CI (initial FAILED, fixed PASSED) и STOPPED для mock-окружения, сохраняя диалоги и квитанции. `make reset` очищает историю всего Compose-экземпляра — для подготовки записи он не нужен.

4. Откройте отдельное приватное окно браузера. В шапке должен быть **Live LLM**, а не Demo Mode.
5. Напишите «Что писать в описании задачи?» — дождитесь ответа со ссылкой. Затем «Проверь PR #17» — дождитесь нового отчёта, правильного SHA и отметки Live LLM. Для исходной версии ожидается ошибка сохранения причины ошибки и FAILED у `TestCreateRepositoryError` в mock CI.

Если пришёл timeout/лимит провайдера или невалидный ответ, используйте «Повторить» и добейтесь корректного результата до записи. Старый отчёт не доказывает успех нового запроса. Внешний бесплатный маршрут может отвечать нестабильно; при показе Demo Mode явно назовите режим. Если хотите заявлять работу с живой моделью, одного Demo-видео недостаточно — сохраните успешный Live-фрагмент.

## 3. Подготовить чистый кадр

После пробного прогона повторите `make demo-reset`. Полностью закройте все приватные окна и откройте новое, чтобы получить отдельную сессию без пробного диалога. Обычная новая вкладка сохраняет cookie и историю.

Закройте редактор `.env`, посторонние вкладки и уведомления. Заранее откройте терминал в корне проекта: в кадре потребуется только `make demo-fixed`. Подготовьте запись экрана средствами, которыми уже пользуетесь. Ускоренные ожидания при монтаже обозначайте; ключевые результаты, SHA и квитанцию оставьте читаемыми.

## 4. Сценарий видео: что писать и что говорить

Вступление: «AI-Buddy — первая линия помощи Backend-стажёру. Он учитывает командные инструкции и помогает подготовить PR к ревью наставника. Модель живая; корпоративные Git, CI и профильные помощники представлены моками».

| Действие | Что показать / сказать |
| --- | --- |
| «Что писать в описании задачи?» | Ответ и открывающуюся ссылку на конкретную инструкцию команды. «Помощник отвечает с опорой на командный контекст». |
| «Как получить доступ к Grafana?» | Роль Viewer, инструкцию и ссылку на демо-заявку. «Buddy объясняет порядок доступа; сам права не выдаёт». |
| «Как получить доступ к GitLab CI/CD?» → «Да» после предложения наставника | Честное отсутствие инструкции и черновик с исходным вопросом. «Если подтверждённого ответа нет, помощник не придумывает его». Черновик не отправляется человеку. |
| «Проверь PR #17» | Live LLM, SHA `a13d9c2…`, `TestCreateRepositoryError` со статусом FAILED, замечание о потере причины ошибки. «Через MCP получены демонстрационные PR и CI; модель анализирует diff по skill и правилам команды». |
| Откройте ссылку `файл:строка`, затем «Объясни замечание 1» | Переход к строке diff и объяснение, почему нужен `%w` для `errors.Is`/`errors.As`. «Стажёр может разобраться в замечании». |
| «Обновить AI-анализ» | Отметьте прежний run ID CI: меняется анализ, а новый запуск CI не создаётся. |
| «Имитировать запуск CI и обновить анализ» | Новый run ID для того же SHA. «Это синтетический запуск CI; код PR не исполняется». |
| В терминале `make demo-fixed`, затем «Обновить AI-анализ» | SHA `c84be19…`, PASSED и исправленный diff. «Для демонстрации выбрана заранее исправленная версия». Модель может оставить дополнительные рекомендации — не обещайте заранее ровно ноль замечаний. |
| «Отправить наставнику» → проверить SHA/наставника → подтвердить | Квитанцию «Запрос создан в демонстрационном Git-сервисе» для нового SHA. «Запись выполняется после подтверждения; реальное сообщение человеку не отправляется». |
| Обновите страницу | Сохранившиеся диалог, отчёт и квитанцию. |

Если по регламенту нужно короткое видео, оставьте один командный вопрос, отсутствие инструкции с черновиком и полный PR-путь. Отпуска/больничный можно показать дополнительным фрагментом. Не нужно выводить в кадр все тестовые логи и весь отчёт покрытия: они идут отдельным приложением.

Финал: «Прототип помогает самостоятельно пройти типовые вопросы и подготовить PR. Следующий шаг — пилот: сравнить время наставника, долю корректных ответов и число рутинных обращений с Buddy и без него». Измеренное снижение нагрузки пока не заявляем. Merge, одобрение наставника и выкат сервис не выполняет: не называйте отправку PR завершённым первым релизом.

## 5. Что отправить на сдачу

1. Ссылку на Git-репозиторий и SHA сдаваемой версии; проверьте доступ жюри.
2. Продуктовую презентацию **PDF**, которую готовит коллега: проблема, пользователь, сценарий, архитектура/моки, результат проверки и методика оценки пользы.
3. Записанное видео или доступную ссылку на него. Проверьте, что оно открывается без вашего аккаунта либо по правам, указанным организаторами.
4. ZIP отчётов из шага 1 или ссылку на него. Проценты берите из его `summary.json`, не из старого сообщения в чате.
5. В репозитории — README, [SDD](sdd.md), `.env.example` без ключей, инструкции запуска и сценарий. Заполненный `.env` остаётся у вас; эксперт может запустить Demo без ключа либо настроить Live своим способом.

Репозиторий не содержит адреса формы сдачи или её ограничений на размер/длительность файлов. Используйте канал и поля организаторов. Если для отчётов нет отдельного поля, положите ZIP рядом с видео/PDF в папку материалов и укажите ссылку в описании сдачи. Не открывайте доступ к папке с ключами или личными данными.

Шаблон сопроводительного текста:

```text
AI-Buddy — первая линия помощи Backend-стажёру и подготовка PR к ревью.
Код: <ссылка на репозиторий>, коммит <SHA>.
Презентация PDF: <файл или ссылка>.
Видеодемо: <файл или ссылка>.
Тесты и покрытие: <ZIP или ссылка>; строки backend <B>%, frontend <F>%.
Запуск и границы: README.md; поведение агента: docs/sdd.md.
Live LLM; Git/CI/профильные помощники — моки. Код PR не исполняется.
```
