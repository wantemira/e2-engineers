# Контрольный прогон и запись демо

Команды PowerShell, сбор ZIP отчётов, подробный текст записи и состав сдачи — в [пошаговой инструкции](submission.md).

Это сценарий для записи на текущем прототипе. Git, CI, документы команды и профильные помощники синтетические. Live-модель подключена через OpenRouter; ключ остаётся в корневом `.env` и не показывается на экране. Перед записью проверьте в `make ps`, что оба контейнера healthy; откройте `http://127.0.0.1:5173/`. Начальные PR и CI восстановите через `make demo-reset`, а для чистого чата откройте новую приватную сессию. `make reset` удаляет историю и квитанции Compose; для обычной записи это не требуется. Проверьте `BUDDY_MODE=live` и `LLM_TIMEOUT=45s` у себя в `.env`, затем выполните `make up`.

## Короткая последовательность

1. Спросите «Что писать в описании задачи?» — покажите ответ и ссылку на раздел команды. Затем «Как получить доступ к Grafana?» — покажите инструкцию Viewer и демо-заявку.
2. Спросите «Как получить доступ к GitLab CI CD?» — покажите, что Buddy не выдумывает доступ и предлагает подготовить вопрос наставнику. Можно ответить «Да», чтобы показать черновик без отправки.
3. Напишите «Проверь PR #17». Покажите выбранный skill, SHA, diff, mock CI, упавший `TestCreateRepositoryError` и конкретное замечание. Скажите вслух: **mock CI не исполняет код PR**.
4. Разберите замечание в чате. Кнопка «Обновить AI-анализ» использует последний доступный CI; «Имитировать запуск CI и обновить анализ» создаёт новый синтетический run ID.
5. Для сравнения исправленного PR выполните в терминале `make demo-fixed`, затем обновите анализ. Новый SHA и PASS относятся к фикстуре. Старый отчёт остаётся в истории.
6. Подтвердите отправку наставнику в интерфейсе. Покажите квитанцию «Запрос создан в демонстрационном Git-сервисе» и её SHA. Реального сообщения человеку сервис не отправляет.

Перед записью сделайте один контрольный Live-запрос по документу и PR. Если внешний вызов вернул ошибку, не выдавайте старый отчёт за новый результат: повторите ту же операцию или запишите воспроизводимый Demo Mode с явной пометкой режима. Скрывать mock-источники и утверждать измеренную экономию времени наставника нельзя. Проверенные технические результаты и команды тестов находятся в [README](../README.md#тесты-и-покрытие) и [SDD](sdd.md).
