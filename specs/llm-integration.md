# ТЗ на подключение LLM к AI-Buddy

Дата проверки тарифов и возможностей провайдеров — 12 ноября 2026 года.

## Решение для MVP

Подписку покупать не требуется. Первый кандидат для внешнего smoke-прогона — OpenRouter с фиксированной бесплатной моделью `openai/gpt-oss-20b:free`. Для независимого воспроизведения оставляем текущий локальный анализатор без ключа. Если бесплатный API недоступен на машине показа, исчерпывает лимит или модель не проходит приёмку, используем Yandex AI Studio с оплатой запросов по токенам. Ollama имеет смысл, если на ноутбуке показа модель укладывается в лимит времени. Доступность аккаунтов и качество ответов на PR проекта предстоит проверить smoke-прогоном.

## Объём работ

1. Добавить реализацию для внешнего API за интерфейсом самопроверки Go-сервиса. Начать с одного внешнего провайдера. Оставить чат по командным документам и локальный анализатор работоспособными в режиме `fixture`. Интеграцию Ollama делать при выборе локальной модели для показа.
2. Настраивать backend через окружение. Добавить `LLM_MODE=fixture|external|ollama`, `LLM_PROVIDER`, `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY`, `LLM_TIMEOUT` и, для Yandex, `LLM_PROJECT_ID`. Внешний режим проверяет обязательную конфигурацию при старте. В `.env.example` указываются только примеры. Ключ хранится в окружении процесса или CI secret.
3. Передавать модели только нужные для текущей проверки данные. Включить версию skill, командные правила, описание задачи, SHA, разрешённые части diff с позициями и данные CI того же SHA. Лимит входа и выхода задаётся в адаптере. При сокращении входа фиксировать пропущенные части в отчёте. Содержимое PR и документов передавать как данные для анализа.
4. Начать с одного запроса со структурированным ответом. Backend сам читает PR и CI через MCP. Для проверки поддержки вызова функций использовать отдельный smoke с разрешённым чтением. Если в основной сценарий потребуется tool calling, разрешить только чтение данных текущего PR и SHA, ограничить число вызовов и повторно проверять аргументы. Запрос наставнику проходит по существующему пути с подтверждением.
5. Схема ответа содержит `assessment.scope`, `assessment.task` и массив замечаний. Для каждого замечания нужны тип `problem` или `assumption`, заголовок, объяснение и рекомендация, опционально позиция и ID правила. Backend проверяет JSON, размеры, разрешённые ID правил и наличие позиции в переданных строках. Ссылки, идентификаторы замечаний и привязку к SHA формирует backend. Существующую проверку SHA после анализа сохранить.
6. Записывать в отчёт фактический режим и модель, показывать их пользователю. При таймауте, 429, 5xx или невалидном ответе показывать понятную ошибку и сохранять предыдущий отчёт. Автоматическая подмена режима запрещена. Для офлайн-демо оператор явно запускает `fixture`. Общий лимит текущего worker — 30 с, стартовый лимит LLM — до 20 с с учётом оставшегося времени операции. Логировать класс ошибки, длительность, модель и число токенов, исключив ключ и содержимое промпта.
7. Добавить серверные лимиты на запросы, токены и параллелизм. Стартовый бюджет прогона — 30 запросов, включая повторы. Превышение возвращает понятную ошибку. Считать реальную стоимость по метрикам выбранного провайдера.

## Приёмка

- `fixture` запускается без ключа и внешней сети. В отчёте видны режим, замечания, оценка задачи и границы анализа.
- Smoke на внешнем API проходит на двух SHA PR №17. Модель возвращает валидную структуру, находит хотя бы один заложенный дефект с точной строкой в исходной версии и не повторяет его после исправления. Фактический CI отображается по данным MCP. Отдельный smoke подтверждает поддержку вызова функции у выбранной пары провайдер и модель.
- На чистом и неполном diff, задаче без описания и недоступном CI агент явно описывает доступные данные и ограничения. Он не заявляет о компиляции, прогоне тестов или полном соответствии задаче по одному diff.
- Автотесты с HTTP-заглушкой покрывают успешный ответ, ошибку ключа, таймаут, 429, невалидную схему, неизвестное правило и выдуманную позицию. Изменение SHA помечает результат устаревшим. Инструкция в синтетическом diff не может вызвать запись или обойти подтверждение.
- Перед показом выполнить по три прогона исходного и исправленного SHA с хоста демо. Зафиксировать модель, валидность ответов, задержки и токены. Если бесплатный маршрут не выдерживает этот прогон, повторить измерение на выбранном резервном варианте.
