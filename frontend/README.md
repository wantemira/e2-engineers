# AI-Buddy frontend

React + TypeScript, Vite, CSS Modules. Интерфейс основан на согласованном макете Figma.

## Запуск

Нужен Node.js 22.12+ или совместимая более новая версия.

```sh
cd frontend
npm ci
npm run dev
```

Локальный адрес — http://127.0.0.1:5173. Команды `npm run build` и `npm test` выполняют проверку типов, production-сборку и тесты HTTP-клиента. Сборка находится в `dist/`.

## Структура

- `src/app` собирает экран, глобальные токены и адаптивную сетку.
- `src/components` содержит общие Button, Dialog и SafeLink.
- `src/features/first-pr/ui` содержит чат, отчёт, замечания и подтверждение отправки.
- `src/features/first-pr/useBuddy.ts` управляет диалогом, историей и операциями.
- `src/features/first-pr/api.ts` выполняет HTTP-запросы и преобразует проверенные ответы API в модели из `types.ts`.

Шрифты и знак AI-Buddy поставляются локально. Сетка адаптируется к узкому экрану, длинные сообщения и пути файлов переносятся. Длинные отчёты и переписка прокручиваются внутри областей на desktop.

## Подключение backend

При открытии интерфейс загружает сохранённые сообщения, проверки и квитанции из `/api/v1/workspace`. Сессию определяет HTTP-only cookie backend. Первое сообщение дожидается загрузки истории, поэтому сохранённые данные сохраняют порядок с новыми ответами. Действия вызывают `/api/v1`. Для локального Go-сервиса Vite проксирует `/api` на `http://127.0.0.1:8080`. Адрес можно изменить через `API_PROXY_TARGET` в `.env`, пример находится в `.env.example`. При отдельном API можно задать `VITE_API_BASE_URL`. Значения `VITE_*` публичны и попадают в сборку. Для production следует настроить reverse proxy для `/api` либо CORS и сессионные cookies на стороне backend.

| Запрос                        | Тело                                                       |
| ----------------------------- | ---------------------------------------------------------- |
| `GET /workspace`              | Сохранённые сообщения, проверки и квитанции текущей сессии |
| `POST /messages`              | `{ "text": "Проверь PR #17" }`                             |
| `POST /self-reviews`          | `{ "pr_ref": "https://…/pull/17" }`                        |
| `POST /review-requests`       | `{ "review_run_id": "…", "expected_mentor_id": "…" }`      |
| `GET /operations/{id}`        | Состояние фоновой операции                                 |
| `POST /operations/{id}/retry` | `{}` для уточнения неопределённого результата              |

Пути в таблице относительны к `/api/v1`. POST принимает `Idempotency-Key` и возвращает `202` с `{ "operation_id": "…" }`. Во время опроса поддерживаются `QUEUED`, `RUNNING`, `SUCCEEDED`, `FAILED` и `RESULT_UNKNOWN`. Повтор сетевого запроса использует прежние ключ и ID операции. Неопределённый результат сохраняется вместе с версией PR и наставником. При повторном открытии подтверждения можно уточнить исходную отправку. Чат и повторная проверка остаются доступными.

Для `SUCCEEDED` ответ содержит `result` с новыми `messages` и необязательными `review` / `review_request`. DTO описаны в `api.ts`, модели интерфейса — в `types.ts`. Имена транспортных полей включают `head_sha`, `created_at`, `is_stale`, `pr_number`. Квитанция с подтверждённым `REQUESTED` обязательна для успешной отправки наставнику. Ошибки имеют `{ "code": "STALE_HEAD", "retryable": false }`. Проверка доступа, фактические статусы и идемпотентность записи выполняются backend и корпоративным сервисом.

Go backend запускается отдельно на `127.0.0.1:8080`, порядок запуска описан в README проекта. В текущем режиме ответы формируются локально по командным файлам. После перезагрузки вкладки frontend восстанавливает завершённые сообщения, проверки и квитанции этой сессии через `/workspace`.
