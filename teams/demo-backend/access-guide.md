# Доступ к рабочим инструментам

Документ задаёт пример процесса для проекта AI-Buddy. Адрес действующей корпоративной системы заявок должен предоставить владелец команды.

## Доступ к инструменту

Укажите инструмент или репозиторий, необходимый уровень доступа и рабочую задачу. Передайте эти сведения наставнику для согласования по процессу команды. Не отправляйте пароли, токены и приватные ключи в чат. Если рабочая форма заявки пока неизвестна, уточните её адрес у наставника. В этом диалоге можно подготовить текст обращения с названием инструмента, причиной и требуемыми правами.

## Grafana

Для чтения командных дашбордов запросите роль Viewer в demo-папке Backend. Владелец ресурса — demo Observability-команда. В заявке укажите рабочую задачу, нужную папку/дашборд и срок доступа. Для просмотра не нужны права Editor или Admin. Перейдите к разделу «Заявка Grafana». Инструкция синтетическая и не выдаёт доступ автоматически.

## Репозиторий

Для работы с учебным репозиторием e2-engineers запросите уровень доступа Developer в demo Git-команде. Владелец — demo Backend-команда. Укажите репозиторий, задачу и нужный уровень доступа; административные права для подготовки PR не требуются. Перейдите к разделу «Заявка Git». Это демонстрационный процесс, не корпоративная система заявок.

## Заявка Grafana

Демонстрационная форма обращения: ресурс — Grafana / Backend, роль — Viewer; добавьте ссылку на рабочую задачу, папку/дашборд и срок доступа. Адресат — demo Observability-команда. На этой странице нет отправки заявки и изменения прав. Реальную ссылку на систему заявок владелец команды может задать в конфигурации AI-Buddy.

## Заявка Git

Демонстрационная форма обращения: ресурс — e2-engineers, уровень — Developer; добавьте задачу и объяснение, зачем нужен доступ. Адресат — demo Backend-команда. Здесь заявка не отправляется; в реальном внедрении URL заменяет владелец команды.
