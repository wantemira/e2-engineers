# AI-Buddy

Первая линия помощи Backend-стажёру: ответы по документам команды, инструкции доступов, направление к профильным помощникам и черновик вопроса наставнику. Основной сценарий — самопроверка PR по командным правилам, объяснение замечаний, повторная проверка и подтверждённый запрос ревью.

Стек: Go 1.26.2, React/TypeScript, MCP, Docker Compose. Командный контекст и Agent Skills хранятся в Markdown/JSON; состояние — в JSON-хранилище.

## Запуск

Нужны Docker с Compose и GNU Make. Из корня репозитория:

```sh
make up
```

Команда проверяет Docker Engine и Compose до сборки. На Windows при выключенном Engine она пытается запустить Docker Desktop и ждёт его готовности до 90 секунд. Docker Desktop должен быть установлен с Linux containers. Проверка отдельно — `make doctor`.

Откройте [http://127.0.0.1:5173/](http://127.0.0.1:5173/). По умолчанию включён **Demo Mode**, ключ модели не требуется. Если порт занят, выполните `make up BUDDY_PORT=5180`.

Для **Live LLM** создайте корневой `.env` по `.env.example`, сохранив значения уже существующего файла. Укажите `BUDDY_MODE=live`, `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY` и `LLM_TIMEOUT=45s`, затем выполните `make up`. Требуется OpenAI-совместимый API с function calling; подробности — в [настройке LLM](docs/llm.md). Режим и модель отображаются в интерфейсе.

| Команда | Действие |
| --- | --- |
| `make ps` / `make logs` | Состояние контейнеров / логи. |
| `make restart` / `make down` | Перезапуск с сохранением данных / остановка. |
| `make demo-reset` | Исходный PR, базовый CI и mock-окружение; история сохраняется. |
| `make demo-fixed` | Исправленная версия PR для повторной проверки. |
| `make reset` | Полная очистка истории и квитанций с повторным запуском. |

Без Docker нужны Go и Node.js 22.12+. В одном терминале запустите `go run ./cmd/api` из `backend`, в другом — `npm ci` и `npm run dev` из `frontend`. API слушает `127.0.0.1:8080`, frontend — `127.0.0.1:5173`. Для Live экспортируйте переменные окружения перед запуском API: сам Go-сервис `.env` не читает.

## Основной сценарий

1. Спросите «Как получить доступ к Grafana?» — появится инструкция со ссылками. Для неизвестного ресурса Buddy предложит уточнение или черновик наставнику.
2. Напишите «Проверь PR #17». Отчёт содержит SHA, замечания со ссылками на diff, правила команды и результаты mock CI.
3. Спросите «Объясни замечание 1». Кнопка «Обновить AI-анализ» использует текущий CI; «Имитировать запуск CI и обновить анализ» создаёт новый синтетический запуск.
4. Выполните `make demo-fixed` и обновите анализ: появятся новый SHA и PASSED. Предыдущие отчёты сохраняются.
5. Подтвердите отправку наставнику. Появится квитанция для проверенного SHA; история и квитанция сохраняются после обновления страницы и перезапуска.

Полная последовательность и ожидаемые результаты — в [демонстрационном сценарии](docs/demo.md).

## Тесты и покрытие

[Скачать готовый отчёт о покрытии и результатах тестов (ZIP)](docs/reports/verification-20261116-123501-693.zip). Проверенная версия — `12b8e1b`, 16 ноября 2026 года.

| Покрытие исполняемых строк | Результат |
| --- | --- |
| Backend | 84,23% |
| Frontend | 87,85% |

После распаковки откройте `backend/coverage.html` и `frontend/coverage/index.html` в браузере. Результаты браузерных тестов — `frontend/playwright-report/index.html`.

Из `backend`: `go test ./...`, `go vet ./...`. Из `frontend`: `npm ci`, `npm test`, `npm run build`, `npm run test:coverage`. Для браузерных тестов установите Chromium командой `npx playwright install chromium` либо задайте `BUDDY_BROWSER_CHANNEL=msedge` для установленного Microsoft Edge. Порты тестов — 4173 и 18080.

Полная проверка с отчётами в PowerShell (Git, Go, Node.js, Microsoft Edge):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify.ps1
```

Результат — `artifacts/verification-<дата>.zip` с SHA кода, логами, HTML/XML/LCOV-отчётами и результатами E2E. Покрытие **исполняемых строк** должно превышать 80% отдельно для backend и frontend. Учитываются все пакеты `backend/cmd`, `backend/internal` и прикладной `frontend/src`, включая файлы без собственных тестов; зависимости, сгенерированный код и тесты исключены. Методика: gocover-cobertura v1.5.0 для Go и Istanbul для TypeScript. Скрипт проверяет контракт Live через тестовый API и не вызывает внешнюю модель.

Учебный `training/orders` — отдельное упражнение с намеренно падающим исходным тестом. Эталон проверяется `make training-solution-test`; запуск сервиса и задания описан в [инструкции](teams/demo-backend/environment-guide.md). Этот модуль не входит в метрику приложения AI-Buddy.

## Границы прототипа

- Git, CI, командные документы и профильные помощники — синтетические. Mock CI не исполняет код PR и не доказывает результат реальной сборки.
- В Live анализ выполняет модель; в Demo — детерминированный mock внутреннего скилла. Источник результата отображается в интерфейсе.
- Запрос ревью создаётся в mock Git после подтверждения. Реальное сообщение наставнику, одобрение, merge и выкат не выполняются.
- Поддерживается одна демо-команда. Измеренное снижение нагрузки наставника пока не заявляется; методика оценки описана в SDD.
