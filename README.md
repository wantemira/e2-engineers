# AI-Buddy

## Запуск через Make

Нужны GNU Make и запущенный Docker с Compose. Из корня проекта:

```sh
make up
```

Compose собирает Go API и фронтенд, проверяет готовность обоих сервисов и открывает AI-Buddy на `http://127.0.0.1:5173/`. Повторный `make up` обновляет существующий стек. Если порт занят другим приложением, задайте свободный, например `make up BUDDY_PORT=5180`, или укажите порт в корневом `.env` по примеру `.env.example`.

| Команда | Действие |
| --- | --- |
| `make restart` | Останавливает стек, освобождает порт и создаёт контейнеры заново с сохранением истории. |
| `make down` | Останавливает стек и освобождает порт. |
| `make reset` | Удаляет историю, проверки и квитанции из тома Compose, выбирает исходный PR, сбрасывает CI и запускает чистый экземпляр. |
| `make build` | Собирает образы. |
| `make ps` | Показывает состояние сервисов. |
| `make logs` | Показывает логи сервисов. |
| `make config` | Проверяет конфигурацию Compose. |
| `make demo-initial` | Выбирает исходный PR, сохраняя историю проверок. |
| `make demo-fixed` | Выбирает исправленную версию PR, сохраняя историю. |
| `make demo-ci CHECKS=PASSED` | Задаёт статус CI выбранной версии. Допустимы UNKNOWN, RUNNING, FAILED и PASSED. |

Compose хранит состояние в именованном томе. При запуске без Docker Go API использует локальную папку `.data/`.

## Запуск без Docker

Запустите Go API и фронтенд в отдельных терминалах из корня проекта. Нужны Go 1.26.2 и Node.js 22.12+.

```powershell
cd backend
go run ./cmd/api
```

```powershell
cd frontend
npm ci
npm run dev
```

Откройте [AI-Buddy](http://127.0.0.1:5173/) и напишите «Как получить доступ к репозиторию?» или «Проверь PR #17». После проверки можно спросить «Объясни замечание 1» и подтвердить отправку наставнику.

Ответы формируются локально по файлам `teams/demo-backend` и правилам `skills/pr-self-review`. Данные PR, CI и квитанция поступают из локального Git-сервиса через MCP. Для проверки исправленной версии выполните `make demo-fixed`, затем нажмите «Проверить повторно». Статусы CI имитируют результат внешней проверки и отображаются после нового запуска самопроверки.

Переключатели демо хранятся в `demo.json` рядом с данными приложения в томе Compose. При запуске без Docker выполните из `backend`:

```sh
go run ./cmd/demo -revision fixed
go run ./cmd/demo -checks FAILED
go run ./cmd/demo -reset
```

Эти команды используют `DATA_DIR` либо папку `.data/` в корне проекта. Для своего расположения данных передайте `-data <путь>`. Команда `demo -reset` возвращает исходный PR и UNKNOWN для CI, сохраняя диалог и квитанции. Полный сброс экземпляра Compose выполняется через `make reset`.

При запуске без Docker API слушает `127.0.0.1:8080`. В Compose браузер обращается к API через прокси фронтенда. Сессия восстанавливается по cookie. Незавершённые операции продолжают опрос по сохранённому ID. При неизвестном результате отправки после перезагрузки доступно «Уточнить результат» с исходными версией PR и ключом действия. Интеграция использует подготовленный PR и локальную квитанцию назначения ревью. Ключ модели для запуска не нужен.

Новые отчёты сохраняют diff проверенной версии PR. Ссылка в замечании открывает нужную строку, даже если PR уже обновился. Чтобы получить такие ссылки для отчёта, сохранённого до этого изменения, запустите проверку повторно.

Для кнопки «Открыть People-агента» укажите в `teams/demo-backend/context.json` поле `"people_agent_url": "https://people.example.test/"` со своим адресом. Если поле отсутствует, чат покажет ссылку на командную инструкцию и черновик вопроса наставнику.

## Учебный сервис стажёра

Спросите в чате «Где тестовое окружение?» — AI-Buddy покажет задание, команды запуска, статус mock-окружения и CI для выбранного SHA PR №17. Ответ сохраняется в истории и содержит ссылку на [инструкцию](teams/demo-backend/environment-guide.md).

В `training/orders` находится самостоятельный Go-сервис с POST /orders и GET /healthz. Задание — сохранить причину ошибки хранилища. Регрессионный тест начальной версии намеренно падает. После исправления `training/orders/internal/orders/service.go` повторите проверку. Для сравнения доступен эталон с build tag `solution`.

```sh
make training-up
make training-test
make training-solution-test
make training-down
```

Учебный сервис доступен по `http://127.0.0.1:8081/healthz`. Порт задаётся переменной `BUDDY_TRAINING_PORT`. Тесты выполняются в отдельном контейнере с отключённой сетью. После изменения кода команды пересобирают соответствующий образ.

Без Docker перейдите в `training/orders`, запустите `go run ./cmd/api`, затем в другом терминале — `go test ./...`. Эталон проверяется командой `go test -tags solution ./...`. Нужен Go 1.26.2. Проверки конкурентного доступа и отмены контекста входят в тесты упражнения.

Статусы окружения и CI в чате являются результатом mock-инструмента. Команды `make demo-environment ENVIRONMENT=READY` и `make demo-ci CHECKS=PASSED` управляют демонстрацией. Фактический результат учебных тестов виден в терминале. Для нового ответа со статусом напишите «Покажи результат тестов». Команда `make reset` очищает историю и возвращает исходный PR, UNKNOWN для CI и STOPPED для mock-окружения.

## Тесты и покрытие

Из `frontend`:

```sh
npm ci
npx playwright install chromium
npm run test:e2e
npm run test:coverage
```

Браузерные тесты запускают Go API и Vite на портах 18080 и 4173 и используют временные данные. Сценарии проверяют путь от сообщения до квитанции, переход к строке diff, повторную проверку, восстановление истории и действия в чате. Для запуска в установленном Microsoft Edge задайте `BUDDY_BROWSER_CHANNEL=msedge` в окружении. Отчёт Playwright находится в `frontend/playwright-report/index.html`, объединённое покрытие Vitest и Playwright — в `frontend/coverage/index.html`. Порог по операторам фронтенда — строго больше 80%.

Из `backend`:

```powershell
New-Item -ItemType Directory -Force coverage | Out-Null
go test ./... "-coverpkg=./internal/..." "-coverprofile=coverage/coverage.out"
go tool cover "-func=coverage/coverage.out"
go tool cover "-html=coverage/coverage.out" "-o=coverage/index.html"
```

Отчёт Go показывает покрытие операторов всех прикладных пакетов в `internal/`. Браузерный сценарий отдельно проверяет запуск API из `cmd/api`. Контракт HTTP описан в `frontend/README.md`.

## Слои backend

- `cmd/api` собирает зависимости и запускает HTTP-сервер и обработчик фоновых операций.
- `internal/transport/httpapi` разбирает HTTP-запросы, управляет cookie и формирует ответы.
- `internal/service` обрабатывает команды чата, проверку PR и отправку на ревью. Здесь определены интерфейсы для хранилища и интеграций.
- `internal/repository` сохраняет сессии, историю и очередь операций. `internal/domain` содержит общие модели.
- `internal/assistant`, `internal/teamconfig` и `internal/integration/mcpgit` реализуют локального ассистента, загрузку командных файлов и работу с Git через MCP.

## Сообщения коммитов

Используем формат Conventional Commits `тип: короткое действие`. В одном коммите собираем одну логически связанную правку. После двоеточия пишем с маленькой буквы и без точки в конце.

| Тип | Когда использовать | Пример |
| --- | --- | --- |
| `feat` | Новая возможность | `feat: добавить самопроверку PR` |
| `fix` | Исправление ошибки | `fix: восстановить историю чата после перезагрузки` |
| `docs` | Документация | `docs: описать локальный запуск` |
| `test` | Тесты | `test: проверить повторную отправку на ревью` |
| `refactor` | Изменение структуры кода с сохранением поведения | `refactor: вынести обработку команд из HTTP-слоя` |
| `chore` | Служебные правки | `chore: добавить правила игнорирования файлов` |
