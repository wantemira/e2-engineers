# AI-Buddy

Запустите Go API и фронтенд в отдельных терминалах из корня проекта. Нужны Go 1.26.2 и Node.js 22.12+.

```powershell
cd backend
go run ./cmd/api
```

```powershell
cd frontend
npm ci
npm run dev
```

Откройте [AI-Buddy](http://127.0.0.1:5173/) и напишите «Как получить доступ к репозиторию?» или «Проверь PR #17». После проверки можно спросить «Объясни замечание 1» и подтвердить отправку наставнику.

Ответы формируются локально по файлам `teams/demo-backend` и правилам `skills/pr-self-review`. Данные PR, CI и квитанция поступают из локального Git-сервиса через MCP. Для проверки исправленной версии поменяйте `current_revision` в `mocks/pr-17.json` на `fixed`, затем нажмите «Проверить повторно».

API слушает `127.0.0.1:8080`. Диалог, проверки и квитанции сохраняются в `.data/` для одной локальной инстанции. Сессия восстанавливается по cookie. Интеграция использует подготовленный PR и локальную квитанцию назначения ревью. Ключ модели для запуска не нужен.

Проверка backend выполняется командой `go test ./...` из `backend`. Контракт HTTP описан в `frontend/README.md`.

## Слои backend

- `cmd/api` собирает зависимости и запускает HTTP-сервер и обработчик фоновых операций.
- `internal/transport/httpapi` разбирает HTTP-запросы, управляет cookie и формирует ответы.
- `internal/service` обрабатывает команды чата, проверку PR и отправку на ревью. Здесь определены интерфейсы для хранилища и интеграций.
- `internal/repository` сохраняет сессии, историю и очередь операций. `internal/domain` содержит общие модели.
- `internal/assistant`, `internal/teamconfig` и `internal/integration/mcpgit` реализуют локального ассистента, загрузку командных файлов и работу с Git через MCP.

## Сообщения коммитов

Используем формат Conventional Commits `тип: короткое действие`. В одном коммите собираем одну логически связанную правку. После двоеточия пишем с маленькой буквы и без точки в конце.

| Тип | Когда использовать | Пример |
| --- | --- | --- |
| `feat` | Новая возможность | `feat: добавить самопроверку PR` |
| `fix` | Исправление ошибки | `fix: восстановить историю чата после перезагрузки` |
| `docs` | Документация | `docs: описать локальный запуск` |
| `test` | Тесты | `test: проверить повторную отправку на ревью` |
| `refactor` | Изменение структуры кода с сохранением поведения | `refactor: вынести обработку команд из HTTP-слоя` |
| `chore` | Служебные правки | `chore: добавить правила игнорирования файлов` |
